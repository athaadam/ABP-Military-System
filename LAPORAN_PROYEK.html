Pendahuluan & Latar Belakang

ABP Military System adalah sistem informasi manajemen logistik militer yang dirancang untuk mendigitalisasi dan mengotomasi pengelolaan inventaris, permintaan penggunaan barang, serta administrasi unit-unit militer di lingkungan Tentara Nasional Indonesia (TNI). Sistem ini dibangun untuk menggantikan proses manual berbasis kertas yang rawan kesalahan, lambat, dan sulit diaudit.

Dengan tiga platform terintegrasi — aplikasi mobile untuk personel lapangan, dashboard web untuk administrator, serta REST API sebagai tulang punggung data — sistem ini memastikan informasi yang konsisten, real-time, dan dapat diakses di mana saja.

ℹ️
Sistem ini mencakup seluruh siklus hidup aset militer: dari pencatatan masuk, permintaan penggunaan oleh personel, persetujuan komando, pengembalian, hingga pencatatan kerusakan dan perbaikan.

Permasalahan yang Diselesaikan

  • Pengelolaan inventaris senjata, amunisi, dan kendaraan militer yang masih manual
  • Tidak adanya alur persetujuan (approval workflow) yang terstandarisasi
  • Kesulitan melacak kondisi dan lokasi barang secara real-time
  • Minimnya audit trail untuk akuntabilitas dan kepatuhan regulasi
  • Ketidakefisienan koordinasi antara unit-unit yang berbeda lokasi

Perancangan Database

6.1 Entity Relationship Diagram (ERD) — Teks

unit (1) ──────────── (N) user unit (1) ──────────── (N) warehouse warehouse (1) ──────── (N) item user (1) ──────────── (N) request [sebagai requester] user (1) ──────────── (N) request [sebagai approvedBy] item (1) ──────────── (N) request request (1) ─────────── (1) return item (1) ──────────── (N) repair item (1) ──────────── (N) item_condition_stock item (1) ──────────── (N) item_condition_mutation_log user (1) ──────────── (N) log

6.2 Deskripsi Tabel

TabelKolom UtamaKeterangan
unit id (VARCHAR PK), name, logo, timestamps Data satuan militer (contoh: MABESAD, KODIM). ID berupa kode unit (bukan auto-increment).
user id (INT AI), name, email (UNIQUE), password, role ENUM, unitId FK Akun pengguna sistem. Role: superadmin / admin / user. Password di-hash dengan bcrypt.
warehouse id (INT AI), name, unitId FK, timestamps Gudang penyimpanan barang. Satu unit dapat memiliki banyak gudang.
item id (INT AI), name, category ENUM, stock, condition ENUM, warehouseId FK, imageUrl Master data barang. Kategori: Persenjataan / Amunisi / Kendaraan Militer. Kondisi: Aktif / Digunakan / Rusak / Perbaikan / Cadangan / Habis.
request id, userId FK, itemId FK, quantity, reason, status ENUM, approvedBy FK Permintaan penggunaan barang. Status: pending → approved / rejected → completed.
return id, requestId FK (1:1), conditionAfter ENUM Pengembalian barang setelah digunakan. Mencatat kondisi barang setelah kembali.
repair id, itemId FK, description, status ENUM Tiket perbaikan barang rusak. Status: pending / in_progress / completed.
item_condition_stock id, itemId FK, condition ENUM, quantity; UNIQUE(itemId, condition) Breakdown stok per kondisi untuk setiap item. Memungkinkan tracking detail kuantitas per status barang.
item_condition_mutation_log id, itemId FK, fromCondition, toCondition, quantity, note, userId FK Log perpindahan kondisi barang (mutation). Audit trail perubahan status stok.
log id, userId FK, action, description, old_value JSON, new_value JSON, created_at Audit trail semua aktivitas sistem. Menyimpan data lama dan baru dalam format JSON untuk perbandingan.

Fitur & Modul Aplikasi

7.1 Modul Autentikasi

Teknologi: JWT (JSON Web Token) + bcryptjs

Alur Login:

  1. Pengguna memasukkan email & password
  2. Backend memverifikasi password dengan bcrypt.compare()
  3. Jika valid, server mengembalikan JWT token (expiry 8 jam)
  4. Client menyimpan token di local storage (mobile: SharedPreferences)
  5. Setiap request API selanjutnya menyertakan Authorization: Bearer <token>
  6. Middleware auth.js memverifikasi token di setiap endpoint terlindungi

Akun Default: superadmin@military.com / SuperAdmin123

Alur permintaan barang mengikuti workflow berikut:

[User membuat permintaan] │ ▼ Status: PENDING ◄────────────────────────────────┐ │ │ ├──── Admin meninjau ────────────────────►│ (bisa ditolak) │ │ Status: APPROVED / REJECTED │ │ │ (jika approved) REJECTED │ ▼ Barang digunakan oleh user │ ▼ User mengembalikan barang │ ▼ Status: COMPLETED + Return Record (kondisi setelah)

7.4 Modul Manajemen Unit Militer

  • CRUD lengkap untuk data satuan/unit militer
  • Upload logo unit (disimpan sebagai Base64 LONGTEXT)
  • ID unit berupa kode tekstual (contoh: MABESAD, KODIM-X)
  • Cascade delete: menghapus unit akan menghapus warehouse & user terkait

7.5 Modul Manajemen Gudang

  • CRUD gudang dengan relasi ke unit
  • Visualisasi kapasitas (occupancy percentage + progress bar)
  • Pengelompokan gudang berdasarkan unit
  • Tracking jumlah item per gudang

7.6 Modul Manajemen Pengguna

  • CRUD pengguna (hanya Admin & Superadmin)
  • Assign role (superadmin / admin / user)
  • Assign unit kepada pengguna
  • Reset password pengguna

Skenario 2: Barang Rusak → Perbaikan

  1. Admin mencatat barang dengan kondisi Rusak
  2. Admin membuat tiket repair (POST /repairs)
  3. Status repair berubah: pending → in_progress → completed
  4. Setelah selesai, kondisi barang diperbarui kembali menjadi Aktif
  5. Mutation log dicatat di tabel item_condition_mutation_log

Keamanan Sistem

🔐 Autentikasi

  • JWT dengan expiry 8 jam
  • Bcrypt password hashing (salt rounds: 10)
  • Auto-logout saat token expired (HTTP 401)
  • Token disimpan di SharedPreferences (mobile)

🛡️ Otorisasi (RBAC)

  • Superadmin: akses penuh ke semua fitur
  • Admin: kelola unit, gudang, user, approval
  • User: browse inventaris & buat permintaan
  • Pemeriksaan role di backend & frontend

🔒 Keamanan Data

  • SQL parameterized queries (anti SQL-injection)
  • Input validation server-side
  • CORS dikonfigurasi via middleware
  • Environment variables via dotenv (.env)

📋 Audit Trail

  • Setiap aksi dicatat di tabel log
  • Menyimpan old_value & new_value (JSON)
  • Timestamp untuk semua event
  • Tidak bisa dihapus oleh user biasa
⚠️
Catatan Keamanan Production: Sebelum deploy ke production, pastikan untuk mengganti password default superadmin, mengkonfigurasi CORS agar hanya menerima domain yang diizinkan, dan menyimpan JWT secret yang kuat di environment variable.

Kesimpulan & Rencana Pengembangan

Kesimpulan

ABP Military System merupakan sistem informasi manajemen logistik militer yang komprehensif dan siap produksi. Sistem ini berhasil menjawab kebutuhan digitalisasi pengelolaan aset militer melalui tiga platform yang terintegrasi secara seamless — mobile (Flutter), web (React), dan API (Node.js/Express).

Dengan implementasi RBAC, audit trail, alur persetujuan terstruktur, serta desain database yang terindeks dengan baik, sistem ini memenuhi standar aplikasi enterprise yang aman, handal, dan dapat dikembangkan lebih lanjut.

✅
Status Proyek: Production Ready
Semua modul utama telah diimplementasikan dan teruji. Sistem siap untuk deployment.

Fitur Selesai

  • CRUD lengkap semua modul (inventaris, permintaan, unit, gudang, pengguna)
  • JWT authentication dengan RBAC 3-level
  • Approval workflow untuk permintaan barang
  • Audit trail semua aktivitas
  • Tracking kondisi barang & mutation log
  • Mobile app dengan Flutter (Android)
  • Web dashboard dengan React
  • Docker deployment untuk backend & database
  • 14 file dokumentasi teknis

Rencana Pengembangan Berikutnya

  • Real-time notifications (WebSocket / FCM Push Notification)
  • Offline mode untuk mobile (local database sync)
  • Biometric authentication (fingerprint / face ID)
  • Advanced reporting & analytics dengan grafik
  • Image upload untuk foto barang (S3 / cloud storage)
  • Multi-language support (i18n: Indonesia / Inggris)
  • Advanced filtering & full-text search
  • Export laporan ke PDF / Excel
  • Backend API v2 dengan GraphQL
  • Unit & integration testing suite
