📊 Entity Relationship Diagram (ERD)

Sistem Manajemen Gudang Militer

Entitas Atribut Keterangan
unit id, name, logo, created_at, updated_at Data satuan/unit militer yang menjadi organisasi induk. Setiap unit memiliki warehouse dan user tersendiri.
user id, name, email, password, role, unitId, created_at, updated_at Data pengguna sistem dengan 3 role: superadmin (kelola seluruh sistem), admin (kelola per unit), user (peminta barang). Berelasi dengan unit melalui unitId.
warehouse id, name, unitId, created_at, updated_at Data gudang/warehouse tempat penyimpanan barang. Setiap warehouse berada dalam satu unit dan dapat menyimpan banyak item barang.
item id, name, category, stock, condition, warehouseId, imageUrl, created_at, updated_at Data inventaris barang/alutsista militer (Persenjataan, Amunisi, Kendaraan Militer). Menyimpan stok dan kondisi dominan item. Berelasi dengan warehouse.
request id, userId, itemId, quantity, reason, status, approvedBy, created_at, updated_at Data permintaan penggunaan barang oleh user. Status: pending → approved/rejected → completed. Berelasi dengan user (peminta dan approver) dan item (barang yang diminta).
return id, requestId, conditionAfter, created_at, updated_at Data pengembalian barang setelah selesai digunakan. Mencatat kondisi barang saat dikembalikan (Aktif, Rusak, Perbaikan). Berelasi dengan request.
repair id, itemId, description, status, created_at, updated_at Data perbaikan untuk item yang rusak atau sedang diperbaiki. Status: pending → in_progress → completed. Berelasi dengan item.
item_condition_stock id, itemId, condition, quantity, created_at, updated_at Tracking stok barang per kondisi (Aktif, Digunakan, Rusak, Perbaikan, Cadangan, Habis). Satu item dapat memiliki stok di berbagai kondisi sekaligus. Composite UNIQUE key pada (itemId, condition).
item_condition_mutation_log id, itemId, fromCondition, toCondition, quantity, note, userId, created_at Log audit untuk setiap perpindahan/mutasi stok barang antar kondisi. Mencatat siapa yang melakukan mutasi (nullable), dari kondisi apa ke apa, dan jumlahnya. Append-only log table.
log id, userId, action, description, old_value, new_value, created_at Catatan audit trail seluruh aktivitas sistem (CREATE_USER, DELETE_USER, RESET_PASSWORD, APPROVE_REQUEST, REJECT_REQUEST). Menyimpan old_value dan new_value dalam JSON untuk tracking perubahan data. Append-only audit log.

📌 Catatan Relasi Database:

  • Primary Key (PK): Setiap entitas memiliki id sebagai primary key
  • Foreign Key (FK): Relasi antar entitas melalui FK dengan ON DELETE CASCADE / ON DELETE SET NULL
  • ENUM Types:
    • user.role: 'superadmin', 'admin', 'user'
    • item.category: 'Persenjataan', 'Amunisi', 'Kendaraan Militer'
    • item.condition: 'Aktif', 'Digunakan', 'Rusak', 'Perbaikan', 'Cadangan', 'Habis'
    • request.status: 'pending', 'approved', 'rejected', 'completed'
    • repair.status: 'pending', 'in_progress', 'completed'
    • return.conditionAfter: 'Aktif', 'Rusak', 'Perbaikan'
  • Indexes: Dibuat pada kolom yang sering di-query (unitId, role, condition, status, userId, itemId, created_at)
  • Timestamps: Setiap entitas mencatat created_at dan updated_at untuk tracking perubahan (kecuali log tables yang hanya append)
